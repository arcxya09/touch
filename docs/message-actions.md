# 消息撤回与本机清理

- 待发消息分别显示「待发送」「发送中」「等待确认」或「发送失败」。网络中断、超时和暂时服务故障不等于服务器拒绝；响应丢失后可由同步确认，手动重试沿用原消息标识，不生成第二条消息。状态写入现有加密待发记录，旧记录按等待确认处理。
- 发送或撤回收到服务器确认后，后续同步故障不会将操作改判为失败。撤回确认后立即收回本机原文、引用与附件访问，不等待下一次全量同步。
- 长按本人已发送消息可选择撤回。服务器校验发送者身份与消息所有权，不限制发送时间；重复撤回成功且不重复产生事件。对方是否在线、登录、打开软件或更新版本不影响服务器操作。
- 撤回保留不含正文、附件或引用的占位记录，仅管理员在聊天历史中看到提示；普通用户的历史、上下文和会话摘要不显示占位记录，通过双方的消息同步事件更新。原附件从服务器删除，原消息引用与发送重试被拒绝。
- `/auth/me` 的 `capabilities` 继续声明服务端支持 `recall-v1`；会话的 `can_recall=true` 供 2.0–2.0.4 客户端正常显示入口。发送方请求头及对方移动会话能力均不作为撤回权限，2.0.5 客户端直接调用服务端撤回接口。历史会话能力数据库列保留以兼容既有迁移，不再触发能力通知或阻止操作。
- 撤回同步沿用 1.0.13 起的 `kind=recalled` 消息状态。1.0.13／1.0.14 虽不发送能力请求头，仍能正确清理单条本机消息、附件及引用，不再被 HTTP 409 错误阻断。普通用户历史、上下文及摘要过滤撤回占位，管理员看到已擦除内容的占位。1.0.12 及更早版本未实现该协议，不能宣称其本机内容已正确清理，但这不阻止服务器撤回。禁止用会清除整段历史的 `clear(seq)` 模拟单条操作。
- 本地删除在当前账号的加密数据库写入消息 ID 标记，并删除本机消息与附件。账号级标记及清理线保存在独立表，退出、重新登录和切换账号时仍保留；物理附件删除失败时保留清理队列并重试。同步、历史、引用和上下文加载都遵守该标记，不调用服务端个人清理接口。
- 设置中的清空本地聊天记录删除消息、附件、草稿和待发送项，保留账号、联系人、配置及同步游标。记录本机时间清理线和当前秒消息 ID，避免恢复旧消息，同时允许当前秒产生的新消息到达。时间清理依赖手机时间正确。
- 删除和撤回会使已打开的本机附件句柄失效，并刷新引用预览和消息通知。已被对方复制、截图或保存到外部应用的内容不能追回；离线设备需联网同步后才更新。
- 撤回需要服务端具备既有撤回接口；发布客户端前核验线上构建和实际接口。2.0.5 直接恢复服务端单方撤回，不新增数据库迁移、不要求重新登录；单独安装客户端不能替代服务端升级。
