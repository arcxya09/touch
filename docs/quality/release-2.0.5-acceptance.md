# 2.0.5 撤回行为修复

2026-10-06，使用者明确要求恢复此前的服务端撤回行为，不应要求对方升级、登录或打开软件。此次沿用已确认的正式修复发布决定，仍如实保留真机专项、历史正式签名包覆盖升级及性能记录未齐全的状态。

历史核验：1.0.13 与 1.0.14 的客户端已实现 `recalled` 精确缓存清理、附件失效、防止已撤回内容被迟到结果恢复、普通用户隐藏与管理员占位。它们不声明 2.0 新增的能力请求头，故此前按请求头和双方移动会话判断支持会阻止既有功能。

修复后，撤回者身份、消息所有权和幂等仍由服务器校验；对方的登录、在线、会话有效期和客户端能力不再影响操作。服务器立即擦除正文、引用和附件，接收端下次正常同步执行单条缓存清理。离线设备上的本机副本须联网同步后才能收到变化，此事实不作为服务器撤回的前置条件。

协议恢复至 1.0.13 起的既有消息状态。不以 `clear(seq)` 模拟单条撤回，因为该事件会删除序号及之前的全部历史。1.0.12 及更早版本不具备精确撤回处理，不能宣称其本机副本已通过此协议清理；这一旧端限制不再阻止服务器操作。

发布前须实际验证对方旧版、退出登录、会话过期及未登记能力等情况，覆盖文本和附件、未授权请求、重复撤回及后续同步不阻塞；同时运行现有 Android 回归与签名、版本、公开下载检查。

本地验证：服务端 SQLite 122 项测试通过，1 项仅 PostgreSQL 执行的测试跳过，Ruff 通过。Android 调试源码及设备测试包编译成功，API 36.1 模拟器执行 12 项撤回、缓存清理与聊天布局回归全部通过。首次运行受到模拟器桌面 ANR 系统窗口抢占焦点干扰；关闭该系统弹窗后使用同一 APK 和原测试重跑，未修改产品或测试来绕过断言。真机、完整多 API 检查、正式签名包和线上部署须按各自实际结果另行记录。
